# Phase 02 — ບັນຊີ, ອົງກອນ ແລະ ສິດເຂົ້າເຖິງ

> ອັບເດດຫຼ້າສຸດ 10 ພະຈິກ 2026: Login ສຳເລັດເຂົ້າ Dashboard ໄດ້ທັນທີ. ຜູ້ໃຊ້ຂໍເອົາໜ້າບັງຄັບປ່ຽນລະຫັດຜ່ານຄັ້ງທຳອິດອອກ; ບັນຊີໃໝ່, reset ແລະ ບັນຊີເກົ່າບໍ່ຖືກກັ້ນດ້ວຍ mustChangePassword ອີກ. ປ່ຽນລະຫັດຜ່ານໄດ້ໃນ `/account` ຕາມຄວາມຕ້ອງການ (6–128 ຕົວ). Username/Password, session, CSRF ແລະ resource permissions ຍັງກວດຈິງຕາມເດີມ. ຂໍ້ຄວາມ first-login gate ເກົ່າຂ້າງລຸ່ມເປັນປະຫວັດ.


> ອັບເດດ 10 ພະຈິກ 2026: ຕາມຄຳຂໍຫຼ້າສຸດ ໜ້າ Login ກວດ Username/Password ກັບ API ຈິງໃນທຸກໂໝດແລ້ວ. ເອົາການກົດຂ້າມແບບ preview ອອກ; `?auth=preview`, `VITE_ENABLE_UI_PREVIEW` ແລະ browser flags ເກົ່າບໍ່ສາມາດຂ້າມ Login. ສ່ວນອະທິບາຍ preview ເກົ່າຂ້າງລຸ່ມເປັນປະຫວັດການພັດທະນາ.
> ໃນ local HTTP development ຮອງຮັບ `localhost`, `127.0.0.1`, `[::1]` ສະເພາະ port ທີ່ຕັ້ງ `APP_ORIGIN`; ຍັງກວດ CSRF ແລະ ປະຕິເສດ cross-site. Production ເຊື່ອໃຈສະເພາະ HTTPS origin ທີ່ຕັ້ງໄວ້.


ວັນທີ: 9 ພະຈິກ 2026
ຂອບເຂດ: ການພັດທະນາ ແລະ ທົດສອບໃນເຄື່ອງທ້ອງຖິ່ນ. ຍັງບໍ່ແມ່ນການອະນຸມັດໃຊ້ງານ production.

## ຂໍ້ຕົກລົງທີ່ຢືນຢັນ

- ຜູ້ໃຊ້ເລືອກໃຫ້ລະບົບຈັດການ Username/Password ເອງ. ບໍ່ໃຊ້ OIDC/Keycloak ໃນ phase ນີ້.
- ບໍ່ໃຫ້ສິດເລີ່ມຕົ້ນ. ສິດອ່ານເກີດຈາກການເປັນເຈົ້າຂອງ, ຂອບເຂດທີ່ກຳນົດ ຫຼື ການແບ່ງປັນລາຍການຢ່າງຊັດເຈນ.
- MFA ຈະເພີ່ມພາຍຫຼັງ ຕາມຄຳຕອບຂອງຜູ້ໃຊ້. ບໍ່ໄດ້ອ້າງວ່າ MFA ໄດ້ເປີດໃຊ້ແລ້ວ.
- ຂໍ້ຄວາມບົນໜ້າເວັບ ແລະ ເອກະສານ Phase 02 ເປັນພາສາລາວ. ຊື່ແບຣນ, URL, ລະຫັດ ແລະ field ທາງເຕັກນິກຄົງເດີມ.

## ຟັງຊັນທີ່ພັດທະນາ

- ເຂົ້າລະບົບດ້ວຍບັນຊີທີ່ຜູ້ດູແລສ້າງໃຫ້. ບໍ່ມີການສະໝັກສາທາລະນະ.
- ເກັບລະຫັດຜ່ານເປັນ Argon2id hash. ບໍ່ເກັບລະຫັດຜ່ານເກົ່າທີ່ສາມາດເປີດເບິ່ງໄດ້.
- ອອກລະຫັດຜ່ານຊົ່ວຄາວ, ບັງຄັບປ່ຽນກ່ອນໃຊ້ງານ, ອອກລະຫັດໃໝ່, ເປີດ/ລະງັບບັນຊີ.
- session ຢູ່ PostgreSQL; browser ເກັບ cookie ແບບ HttpOnly. ຖານຂໍ້ມູນເກັບພຽງ hash ຂອງ session token.
- ກວດ Origin ແລະ CSRF ໃນການປ່ຽນຂໍ້ມູນ, ຈຳກັດການລອງ Login, ກວດວັນໝົດອາຍຸ ແລະ ສະຖານະບັນຊີໃນທຸກຄຳຂໍ.
- ການປ່ຽນ/ອອກລະຫັດຜ່ານໃໝ່ ແລະ ການລະງັບບັນຊີ ຢຸດ session ເກົ່າ. ການອອກຈາກລະບົບຖອນ session ປັດຈຸບັນ.
- ຈັດການຜູ້ໃຊ້, ພະແນກ, ສະມາຊິກ, ຜູ້ດຳລົງຕຳແໜ່ງ ແລະ ບົດບາດຕາມຂອບເຂດ. ເກັບວັນເລີ່ມ/ສິ້ນສຸດປະຫວັດ.
- ການແບ່ງປັນໃຫ້ຜູ້ໃຊ້/ພະແນກ ແລະ ການຖອນສິດໃຊ້ policy ດຽວກັນ. ກັ່ນຕອງສິດກ່ອນແບ່ງໜ້າ ແລະ ນັບລາຍການ.
- ບັນທຶກ audit ຂອງການຈັດການບັນຊີ ແລະ ສິດ. ບັນຊີ runtime ບໍ່ມີສິດແກ້ໄຂ/ລຶບປະຫວັດ audit ໃນຖານຂໍ້ມູນ.
- ປັບການເຊື່ອມຕໍ່ PostgreSQL ໃຫ້ໃຊ້ UTC ເພື່ອໃຫ້ວັນເລີ່ມສິດ ແລະ session ຖືກຕ້ອງໃນເຄື່ອງທີ່ໃຊ້ Asia/Vientiane.
- ໜ້າ Login ຕາມ component ທີ່ຜູ້ໃຊ້ໃຫ້: ຮູບດ້ານຊ້າຍ, ຟອມ Dark Mode ດ້ານຂວາ, ແສດງ/ເຊື່ອງລະຫັດຜ່ານ ແລະ ຈື່ການເຂົ້າໃຊ້ແບບຈຳກັດເວລາ.
- ຮູບ ແລະ Noto Sans Lao ເກັບໃນໂປຣເຈັກ; ບໍ່ຕ້ອງໂຫຼດຈາກ CDN ໃນຂະນະໃຊ້ງານ.

## ການທົດສອບ

ໃຊ້ `pnpm test` ສຳລັບ API ພື້ນຖານ ແລະ `pnpm test:identity` ສຳລັບຖານຂໍ້ມູນທົດສອບທີ່ສ້າງແຍກ. ຄຳສັ່ງທີສອງບໍ່ທົດສອບດ້ວຍການຂຽນທັບ `lapnet_dev`; ຈະສ້າງ ແລະ ລຶບສະເພາະຖານຂໍ້ມູນຊົ່ວຄາວຂອງຕົນເອງ.

ກໍລະນີຫຼັກ: Login, ລະຫັດຜ່ານຜິດ, ການປອມ role/identity, CSRF/Origin, ສິດຜູ້ດູແລທີ່ບໍ່ເປີດຂໍ້ມູນວຽກ, ຂອບເຂດພະແນກ, ແບ່ງປັນໜຶ່ງລາຍການ, ຖອນສິດ, ສະມາຊິກທີ່ຍັງບໍ່ເຖິງວັນເລີ່ມ, ລະງັບບັນຊີ, ປ່ຽນ/ອອກລະຫັດໃໝ່, session ໝົດອາຍຸ, ຜູ້ດູແລຄົນສຸດທ້າຍ ແລະ audit ທີ່ບໍ່ມີລະຫັດຜ່ານ.

## ຂອບເຂດທີ່ຍັງບໍ່ແມ່ນ production

ໜ້າວຽກ, ໂພສ, ເອກະສານ ແລະ ບໍລິສັດຍັງໃຊ້ຂໍ້ມູນທົດລອງ. ງານທີ່ເພີ່ມໃນໜ້າທົດລອງຍັງຫາຍເມື່ອໂຫຼດໜ້າໃໝ່; ການບັນທຶກວຽກຈິງເປັນ Phase 03. ສິດເຂົ້າເຖິງຖືກທົດສອບໃນ API ຂອງ resource ແທ້ ແລະ ຕ້ອງນຳໃຊ້ກັບທຸກ business module ຕໍ່ໄປ.

ຍັງຕ້ອງກວດ Docker, HTTPS, ການແຍກ staging/production, ອຸປະກອນ backup ແຍກ ແລະ ຂະໜາດວຽກໃນ server ບໍລິສັດ. ປຸ່ມ Google/GitHub ແລະ ເສັ້ນຄັ່ນຖືກເອົາອອກຕາມຄຳຂໍລ່າສຸດ.

## ໂໝດສະແດງຕົວຢ່າງຕາມຄຳຂໍລ່າສຸດ

ໃນ development, ປຸ່ມໜ້າ Login ເຂົ້າໜ້າຕົວຢ່າງໄດ້ທັນທີໂດຍບໍ່ກວດຊ່ອງກອກ. ບໍ່ສົ່ງ password ແລະ ບໍ່ສ້າງ server session. ໜ້າຈັດການໃນໂໝດນີ້ໃຊ້ຂໍ້ມູນຕົວຢ່າງ, ບໍ່ປ່ຽນບັນຊີ/ສິດຈິງ.

API ຈິງຍັງກວດບັນຊີ ແລະ ສິດ. Production build ບໍ່ເປີດໂໝດນີ້. ເພື່ອທົດສອບ Login ຈິງໃນ development, ໃຊ້ `/sign-in?auth=real` ຫຼື ຕັ້ງ `VITE_ENABLE_UI_PREVIEW=false` ແລ້ວຮັນ web ໃໝ່. ສະຖານະ preview ຢູ່ sessionStorage ເປັນ flag ທົ່ວໄປ; ບໍ່ເກັບ password ຫຼື token.
